# Beyond Pixells — Brand Playbook

> The master rules for how the brand looks, speaks and positions itself.
> Sources: full research in `docs/research/` (12 reports, 2026-09-25).

---

## 1. Positioning (locked)

> **Beyond Pixells is a modern product studio that builds sector-specific
> operating systems and custom digital solutions to automate, digitize and
> scale local businesses.**

Hero line (site, decks, bios): **"We build operating systems for local businesses."**

- Alternative A: "The modern software studio powering local enterprise."
- Alternative B: "Vertical software. Modern design. Unfair operational advantage."

## 2. Brand Architecture — Endorsed Hybrid

```
BEYOND PIXELLS (the studio / master brand)
│
├── The OS Family (sub-brands, one naming pattern)
│   ├── Gym OS      — live
│   ├── Dentist OS  — live demo
│   └── Builder OS  — in development
│
├── Standalone Ventures (own identities)
│   ├── Bloomwire   — flower e-commerce
│   └── FORTREX FX  — trading tournaments
│
└── Services (under master brand)
    ├── Custom OS rollouts
    ├── Websites & landing pages
    ├── Automation & integrations
    └── Digital products (kits, templates, playbooks)
```

Rules:
- The studio brand endorses every product: "Gym OS — by Beyond Pixells."
- The `__ OS` pattern is protected by consistency: every OS must be a full
  operating system (website + portal + dashboard + automation), never a lone app.
- Ventures with a different audience (Bloomwire, FORTREX) keep standalone names
  but appear in the studio's "Ventures" section.
- Spelling is **Beyond Pixells** — always. Audit and fix "Beyond Pixels" on sight.

## 3. Message Hierarchy (homepage flow)

1. **Hero:** operating systems for local businesses → what a product studio is
2. **Products:** the OS family grid (live → demo → in development, honestly labeled)
3. **Philosophy:** generic software vs thin templates → we build the third option
4. **Services:** the studio behind the software
5. **Proof:** only verified production numbers — never invented testimonials
6. **Process:** research → build → rollout → automate
7. **CTA:** WhatsApp (primary channel for Indian buyers)

## 4. Voice & Tone

- Confident, specific, zero hype-words ("revolutionary", "game-changing" banned).
- Numbers over adjectives: "8 client systems live", not "many happy clients".
- India-native: WhatsApp-first, UPI, rupees, Hindi/Hinglish allowed in ads.
- Never fake proof. Unlaunched products say "in development", not "coming soon™".

## 5. Visual System (applies across all properties)

- Canvas `#08090C`, cards `#12141A`, strokes `rgba(255,255,255,.08)`
- Signature gradient: `#FF3B30 → #FF7A00` (crimson → amber) — the "kinetic pulse"
- Status accent: electric cyan `#00F2FE` for live/real-time indicators
- Type: **Space Grotesk** (display) + **Plus Jakarta Sans** (body)
- Cards: 16px radius, frosted glass, hover glow — never rainbow colors, never
  hardcoded light themes, one accent family per page
- Every product site in the family shares this DNA (fonts, buttons, spacing)
  while taking on its industry's imagery

## 6. Naming & Expansion Rules

- New vertical products automatically follow: `[Industry] OS`.
- Before building a new OS: run the 7-research exercise (competitors, psychology,
  landing, visuals, legal, audit, roadmap) — the playbook exists in `docs/research/`.
- One shared platform core (auth, payments, WhatsApp engine, lead engine,
  notifications) is reused across every OS — never rebuild the spine.
